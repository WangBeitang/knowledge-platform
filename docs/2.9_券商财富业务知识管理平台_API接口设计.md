# 券商财富业务知识管理平台：API 接口设计

## 0. 文档用途

本文定义平台对前端、后续问问小安以及原 RAG（检索增强生成）暴露或调用的 API（应用程序接口）契约。执行 Agent（执行智能体）必须以本文为实现基线，不得临时扩大权限、改变字段语义，或让客户端自行选择 Dataset（知识库）。

配套文档：

- [概要设计总纲](./2.9_券商财富业务知识管理平台_概要设计总纲.md)
- [数据对象设计](./2.9_券商财富业务知识管理平台_数据对象设计.md)

平台接口统一使用 Base Path（基础路径）`/api/v1`；上游接口指原 RAG（检索增强生成）现有服务接口。

---

## 1. 全局接口规范

### 1.1 格式与校验

- 普通请求和响应使用 `application/json`；文件导入使用 `multipart/form-data`；问答使用 SSE（服务端事件流）`text/event-stream`；
- 字段统一使用 `snake_case`（小写下划线命名）；时间输出带时区 ISO 8601；
- Pydantic（数据契约校验）模型默认 `extra="forbid"`，拒绝未声明字段；
- 平台主键使用 UUID；原 RAG（检索增强生成）ID 原样保存；
- Token（模型计量单位）无法取得时返回 `null`，不得估算或用 0 代替。

### 1.2 请求追踪

客户端可传 `X-Request-Id`，未传时平台生成 UUID。响应头、响应体、日志和管理员写操作审计必须使用同一个 `request_id`。

普通成功响应：

```json
{"request_id":"uuid","data":{}}
```

分页查询参数统一为 `page`（默认 1）、`page_size`（默认 20，最大 100）、`sort_by`（接口白名单）和 `sort_order`（`asc` 或 `desc`）。

```json
{
  "request_id": "uuid",
  "data": {"items": [], "page": 1, "page_size": 20, "total": 0}
}
```

错误响应：

```json
{
  "request_id": "uuid",
  "error": {
    "code": "DOCUMENT_NOT_FOUND",
    "message": "文档不存在或无权访问",
    "retryable": false,
    "details": {}
  }
}
```

`message`（错误说明）可向用户展示，不得包含堆栈、数据库语句、密钥和上游原始内部异常。

### 1.3 幂等性（v1.1 修订：移除通用 Idempotency-Key）

本平台**不实现通用 `Idempotency-Key`（幂等键）机制**（v1.0 的通用幂等要求已由执行基线确认简化，同时移除 `IDEMPOTENCY_CONFLICT` 错误码）。写操作的防重依赖业务级幂等：

- Dataset（知识库）初始化：先查后建，重复执行返回已有结果，不重复创建；
- FAQ（常见问题）文档同步：相同范围、相同 `content_hash`（内容哈希）已成功时直接幂等返回；
- 文档替换与 FAQ（常见问题）文档清理：由长任务状态机配合数据库行锁，保证删除动作只执行一次。

## 2. 鉴权与权限

### 2.1 内部鉴权

内部接口使用 `Authorization: Bearer <jwt>`。JWT（登录令牌）至少包含 `sub`（用户 ID）、`sid`（登录会话 ID）、`jti`（令牌唯一 ID）、`role`（用户角色）、`iat`（签发时间）、`exp`（到期时间）。

每次请求必须检查签名、到期时间、会话是否撤销、用户是否 `active`，以及签发时间是否早于最近密码变更时间；不能只相信令牌中的角色。

### 2.2 外部服务鉴权

后续问问小安只使用 `X-Service-Key: <service_api_key>`：

- 密钥只从环境变量读取，不进入数据库、日志、审计或前端；
- 外部请求固定映射 `external_public`（外部公开）；
- 外部请求 Schema（数据结构）不得声明 `knowledge_scope`、`dataset_id` 或 `dataset_ids`；
- 请求出现以上字段时返回 HTTP `422`，不得静默忽略。

### 2.3 权限矩阵

| 能力 | 管理员 | 普通员工 | 外部服务 |
|---|:---:|:---:|:---:|
| 平台登录 | 是 | 是 | 否 |
| 查询外部公开知识 | 是 | 是 | 是 |
| 查询内部共享知识 | 是 | 是 | 否 |
| 查询管理员专属知识 | 是 | 否 | 否 |
| 用户、文档、Chunk、FAQ、缺口、看板、审计管理 | 是 | 否 | 否 |
| 员工反馈 | 不提供 | 不提供 | 不提供 |

资源无权访问时优先返回 `404`，避免泄露管理员专属资源是否存在。

## 3. 稳定错误码

| HTTP | 错误码 | 语义 | 可重试 |
|---:|---|---|:---:|
| 400 | `INVALID_REQUEST` | 业务参数无效 | 否 |
| 400 | `EMPTY_QUESTION` | 归一化后问题为空 | 否 |
| 401 | `AUTH_REQUIRED` | 未登录或令牌无效 | 否 |
| 401 | `SERVICE_AUTH_FAILED` | 外部服务密钥错误 | 否 |
| 403 | `PERMISSION_DENIED` | 已鉴权但无权限 | 否 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在或不可见 | 否 |
| 409 | `RESOURCE_CONFLICT` | 资源状态冲突 | 否 |
| 409 | `INDEX_VERSION_CONFLICT` | Chunk（文本块）索引版本变化 | 否 |
| 413 | `FILE_TOO_LARGE` | 文件超过限制 | 否 |
| 415 | `UNSUPPORTED_FILE_TYPE` | 文件类型不支持 | 否 |
| 422 | `VALIDATION_ERROR` | Schema（数据结构）校验失败 | 否 |
| 429 | `RATE_LIMITED` | 访问频率超限 | 是 |
| 502 | `RAG_BAD_RESPONSE` | 上游响应违反契约 | 是 |
| 503 | `RAG_UNAVAILABLE` | 原 RAG（检索增强生成）不可用 | 是 |
| 504 | `RAG_TIMEOUT` | 上游调用超时 | 是 |
| 500 | `INTERNAL_ERROR` | 未预期错误 | 视情况 |

### 4.1 健康检查

| 方法与路径 | 鉴权 | 用途 |

| `GET /api/v1/health/live` | 无 | 仅证明进程存活 |
| `GET /api/v1/health/ready` | 无 | 检查 MySQL、Redis、RAG 查询和导入服务 |

就绪响应可为 `ok` 或 `degraded`（降级），必须逐组件展示状态，不能返回密钥或连接串。

## 6. RAG 连接与知识库初始化

仅管理员可访问。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/v1/admin/integration/rag/status` | 查看服务和三档 Dataset（知识库）状态 |
| `POST /api/v1/admin/integration/rag/bootstrap` | 幂等创建或校验三档 Dataset 及固定服务身份 |
| `GET /api/v1/admin/integration/tasks/{task_id}` | 查询平台长任务及上游最新状态 |

初始化请求：

```json
{"verify_only":false}
```

三档映射固定为：

```text
external_public -> RAG_EXTERNAL_DATASET_ID
internal_shared -> RAG_INTERNAL_DATASET_ID
admin_private   -> RAG_ADMIN_DATASET_ID
```

环境变量提供实际 Dataset ID。页面只传知识范围，不传实际上游 ID。

任务响应至少包含 `id`、`operation`、`status`、`rag_status`、`done_nodes`、`running_nodes`、`failed_node`、安全错误摘要和更新时间。未知上游状态不得映射成成功。

## 7. 文档管理

本节仅管理员可访问。

### 7.1 导入

`POST /api/v1/admin/documents/import`，使用 `multipart/form-data`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|:---:|---|
| `files` | File[] | 是 | 一个或多个文件 |
| `knowledge_scope` | string | 是 | 三档范围之一 |

页面可选多个文件，但平台必须逐个调用原 RAG（检索增强生成）的单文件上传接口，并返回逐文件结果：

```json
{
  "request_id": "uuid",
  "data": {
    "items": [
      {"file_name":"业务手册.pdf","task_id":"uuid","document_id":"uuid","status":"pending"},
      {"file_name":"bad.exe","status":"rejected","error":{"code":"UNSUPPORTED_FILE_TYPE","message":"不支持该类型"}}
    ]
  }
}
```

部分失败不回滚已成功提交的文件。

### 7.2 查询、重建、替换和删除

| 方法与路径 | 用途 |
|---|---|
| `GET /api/v1/admin/documents` | 分页列表，筛选范围/状态/文件名/来源 |
| `GET /api/v1/admin/documents/{document_id}` | 详情及上游最新快照 |
| `POST /api/v1/admin/documents/{document_id}/rebuild` | 沿用原 RAG 逻辑重建 |
| `POST /api/v1/admin/documents/{document_id}/replace` | 上传新文件并替换旧文件 |
| `DELETE /api/v1/admin/documents/{document_id}` | 删除上游检索产物并软删平台映射 |

替换固定顺序：新文件导入同一范围 → 新文件成功 → 删除旧文档 → 写替换记录 → 旧映射标为 `replaced`。新文件未成功前绝不删除旧文档。

删除固定语义：Milvus Chunk（向量文本块）物理删除、MongoDB（文档数据库）文档元数据软删除、图片前缀删除、源文件不删除。接口不提供“是否删除源文件”参数。

## 8. Chunk 管理

仅管理员可访问。平台不保存 Chunk（文本块）正文。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/v1/admin/documents/{document_id}/chunks` | 分页查询 Chunk |
| `GET /api/v1/admin/documents/{document_id}/chunks/{chunk_id}` | 查询详情 |
| `PATCH /api/v1/admin/documents/{document_id}/chunks/{chunk_id}/enabled` | 启用或禁用 |

启停请求：

```json
{
  "enabled": false,
  "reason_code": "outdated_content",
  "reason_text": "旧版制度内容",
  "expected_index_version": 3
}
```

`reason_code` 只允许 `parse_error`、`header_footer`、`garbled_text`、`outdated_content`、`human_misjudgment`、`manual_restore`、`other`。索引版本不一致返回 `INDEX_VERSION_CONFLICT`。

禁止提供编辑 Chunk（文本块）正文的接口；内容有问题时先禁用，再修复源文档或重建。

## 9. 内部会话与问答

管理员和普通员工只能操作自己的会话。本期不提供管理员查看其他员工聊天内容的能力。

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/chat/sessions` | 新建会话 |
| `GET /api/v1/chat/sessions` | 查询自己的会话 |
| `GET /api/v1/chat/sessions/{session_id}` | 查询自己的会话和消息 |
| `PATCH /api/v1/chat/sessions/{session_id}` | 修改标题或归档 |
| `DELETE /api/v1/chat/sessions/{session_id}` | 软删除自己的会话 |
| `POST /api/v1/chat/sessions/{session_id}/messages:stream` | 内部流式问答 |

问答请求只有问题：

```json
{"question":"客户如何办理风险测评？"}
```

请求体不得包含知识范围。服务端根据角色固定计算：

```text
admin    -> [admin_private, internal_shared, external_public]
employee -> [internal_shared, external_public]
```

处理顺序：问题归一化 → 按范围优先级做 FAQ 精确匹配 → 未命中则调用原 RAG（检索增强生成）→ 保存消息与访问日志 → 异步补取 Trace（执行追踪）的真实 Token（模型计量单位）。原 RAG 不可用时明确报错，不允许平台自行生成无来源答案。

## 10. 外部问答接口

当前版本实现接口和 Contract Test（契约测试），不立即改问问小安。只有平台、原 RAG（检索增强生成）改造和双方验收通过后，才开始对接问问小安。

`POST /api/v1/external/knowledge/messages:stream`

请求头：`X-Service-Key`、`Content-Type: application/json`、`Accept: text/event-stream`。

```json
{
  "external_session_id": "xiaosan_session_001",
  "external_user_id": "customer_opaque_id",
  "question": "如何查看账户的风险等级？"
}
```

约束：会话 ID 1～120 字符，用户 ID 1～200 字符，问题 1～4000 字符且归一化后非空。外部用户 ID 只保存加盐哈希，只用于 UV（独立访客数）、日志关联和限流，不参与权限计算。

服务端固定值：

```text
allowed_scopes   = [external_public]
rag_dataset_ids  = [RAG_EXTERNAL_DATASET_ID]
rag_service_user = RAG_SERVICE_USER_EXTERNAL
```

不接受角色、客户等级、产品权限、知识范围和 Dataset（知识库）字段。

## 11. SSE 事件契约

内部和外部问答使用同一事件结构，每个事件包含 `request_id` 和 `turn_id`。

```text
event: ready
data: {"request_id":"uuid","turn_id":"uuid","session_id":"uuid"}

event: progress
data: {"request_id":"uuid","turn_id":"uuid","stage":"faq_lookup","message":"正在检索常见问题"}

event: delta
data: {"request_id":"uuid","turn_id":"uuid","text":"办理风险测评可"}

event: final
data: {"request_id":"uuid","turn_id":"uuid","answer":"...","answer_source":"rag","trace_id":"trace_xxx","citations":[],"terminal_reason_code":"completed"}
```

允许的 `stage`（阶段）：`faq_lookup`、`rag_submit`、`rag_progress`、`finalizing`。`delta`（答案增量）只用于 RAG 流式文本；FAQ 精确命中可直接发 `final`（最终结果），其 `answer_source` 为 `faq_cache`、`trace_id` 为 `null`、`citations` 为 `[]`，不得伪造引用。

失败事件：

```text
event: error
data: {"request_id":"uuid","turn_id":"uuid","code":"RAG_UNAVAILABLE","message":"知识检索服务暂时不可用，请稍后重试","retryable":true}
```

`final` 和 `error` 只能出现一个，且必须是最后一个业务事件。连接断开不等于任务失败；平台可查询上游状态完成持久化，本期不做断线续传。

## 12. FAQ 管理

仅管理员可访问。

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/admin/faq-candidates/analyze` | 手动按精确归一化值分析高频问题 |
| `GET /api/v1/admin/faq-candidates` | 分页查看候选 |
| `POST /api/v1/admin/faq-candidates/{candidate_id}/reject` | 拒绝候选 |
| `POST /api/v1/admin/faq-candidates/{candidate_id}/publish` | 审核并发布 |
| `GET /api/v1/admin/faqs` | 分页查询正式 FAQ |
| `POST /api/v1/admin/faqs` | 直接创建并发布 |
| `PATCH /api/v1/admin/faqs/{faq_id}` | 更新完整可变字段 |
| `POST /api/v1/admin/faqs/{faq_id}/unpublish` | 下线，不物理删除 |
| `POST /api/v1/admin/faqs/{faq_id}/publish` | 重新发布 |
| `POST /api/v1/admin/faqs/{faq_id}/sync:retry` | 重试对应范围 RAG 同步 |
| `GET /api/v1/admin/faq-sync-runs` | 查看同步记录 |

发布请求：

```json
{
  "knowledge_scope": "internal_shared",
  "question": "如何办理风险测评？",
  "answer": "请通过……完成风险测评。"
}
```

发布成功后先提交 MySQL（关系型数据库）正式状态并刷新 Redis（缓存数据库）精确缓存，再触发对应范围 FAQ Markdown（常见问题文档）同步。RAG 同步失败不回滚已审核 FAQ。

三档范围分别生成三份汇总文档，不能合成一份后依赖 Chunk（文本块）权限过滤。平台 FAQ 只做归一化精确匹配；未命中后，原 RAG 可通过这三份文档进行语义检索。

## 13. 知识缺口、看板与审计

仅管理员可访问。

### 13.1 知识缺口

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/admin/knowledge-gaps/analyze` | 手动分析候选 |
| `GET /api/v1/admin/knowledge-gaps` | 分页查看候选 |
| `POST /api/v1/admin/knowledge-gaps/{gap_id}/ignore` | 忽略 |
| `POST /api/v1/admin/knowledge-gaps/{gap_id}/resolve` | 标记已处理 |

知识缺口只是候选。仅在 RAG 正常完成但无 Citation（引用来源）或明确证据不足时产生；鉴权失败、超时、系统错误和上游不可用不得产生。

### 13.2 运营看板

| 方法与路径 | 用途 |
|---|---|
| `GET /api/v1/admin/dashboard/summary` | PV、UV、问答量、成功率、延迟、Token |
| `GET /api/v1/admin/dashboard/trends` | 按日或小时趋势 |
| `GET /api/v1/admin/dashboard/top-questions` | 高频问题 |
| `GET /api/v1/admin/dashboard/top-documents` | 高频引用文档 |

通用参数为 `date_from`、`date_to`、`channel`；排行另有 `limit`（最大 100）。Token（模型计量单位）必须同时返回 `token_coverage_rate`（真实 Token 数据覆盖率），缺失值为 `null`。

### 13.3 审计

`GET /api/v1/admin/audit-logs`

必须审计用户变更、知识库初始化、文档导入/重建/替换/删除、Chunk 启停、FAQ 发布/修改/下线/同步重试、知识缺口处理。响应和日志禁止包含密码、JWT、Service API Key（服务调用密钥）、连接串、完整文档正文和模型隐藏推理。

## 14. 平台到原 RAG 的接口映射

平台只通过 Adapter（适配层）调用原 RAG（检索增强生成）；路由层禁止直接拼上游 URL。

### 14.1 固定服务身份

| 场景 | 上游 `X-User-Id` | 允许 Dataset（知识库） |
|---|---|---|
| 管理员操作 | `RAG_SERVICE_USER_ADMIN` | 三档全部 |
| 员工查询 | `RAG_SERVICE_USER_EMPLOYEE` | 外部公开、内部共享 |
| 外部查询 | `RAG_SERVICE_USER_EXTERNAL` | 仅外部公开 |

平台仍记录真实内部用户或外部匿名标识，但不把全部平台用户同步到原 RAG。

### 14.2 查询映射

| 平台动作 | 原 RAG 接口 |
|---|---|
| 提交查询 | `POST /query`，显式传 `dataset_ids` |
| 读取流 | `GET /stream/{session_id}` |
| 查询状态 | `GET /status/{session_id}` |
| 查询 Trace | `GET /traces/{trace_id}` |

内部适配请求示例：

```json
{
  "query": "客户如何办理风险测评？",
  "session_id": "rag_scoped_session_id",
  "dataset_ids": ["securities_internal_shared","securities_external_public"]
}
```

平台不得把客户端任意值直接放入 `dataset_ids`。上游会话 ID 由平台生成或加命名空间，避免内外会话碰撞。

### 14.3 Dataset 与文档映射

| 平台动作 | 原 RAG 接口 |
|---|---|
| Dataset 创建/查询 | `POST /datasets`、`GET /datasets`、`GET /datasets/{dataset_id}` |
| 成员查询/增删改 | `/datasets/{dataset_id}/members` 相关 GET/POST/PATCH/DELETE |
| 单文件上传 | `POST /upload`，字段 `files`、`dataset_id`、`visibility` |
| 查询导入任务 | `GET /status/{task_id}` |
| 文档列表/详情/任务 | `GET /documents`、`GET /documents/{document_id}`、`GET /documents/{document_id}/tasks` |
| Chunk 列表/详情/启停 | `GET /documents/{document_id}/chunks`、详情和 `PATCH .../enabled` |
| 文档重建/删除 | `POST /documents/{document_id}/rebuild`、`DELETE /documents/{document_id}` |

页面多文件上传不等于上游批量上传；适配层必须循环提交单文件并保留逐文件任务。

### 14.4 兼容边界

- 原 RAG（检索增强生成）设备运维默认 Dataset 保留，不修改；券商 Dataset 由平台显式指定；
- 原 RAG 已有网络搜索逻辑保持不变，平台不增加外部查询专属限制；
- 因此外部本地 Dataset 隔离不等于答案只能来自本地公开文档，这是已接受的第一版边界；
- 原 RAG 新字段先由适配层兼容，不能直接穿透使前端契约漂移。

## 15. 超时、重试与降级

| 调用 | 建议超时 | 自动重试 |
|---|---:|---|
| 健康检查、列表、详情 | 3～10 秒 | 网络错误最多 2 次，指数退避 |
| 提交 RAG 查询 | 15 秒 | 确认接收后不重复提交 |
| SSE 读取 | 按原 RAG 合理上限 | 断开后查状态，不自动生成第二问 |
| 文件上传 | 按大小配置 | 无业务幂等保证时不自动重传 |
| Trace 查询 | 5 秒 | 最多 2 次，最终缺失则 Token 为 `null` |

降级规则：

- Redis 不可用：FAQ 精确查询回退 MySQL；
- FAQ RAG 同步失败：精确 FAQ 继续服务并显示可重试状态；
- RAG 不可用：已缓存或 MySQL 命中的精确 FAQ 仍可返回，未命中则明确报错；
- MySQL 不可用：平台未就绪，不能绕过平台权限直接调用 RAG；
- 看板 Token 缺失：显示 `null` 或“暂无数据”，不得估算。

## 16. 安全与版本规则

- 外部接口按 Service API Key 和外部用户哈希限流；登录按用户名和 IP 限流；
- 上传校验扩展名、MIME（媒体类型）、大小和文件名，文件名不得直接作为服务器路径；
- CORS（跨域资源共享）只允许部署配置中的平台前端来源；
- SQL 使用 ORM（对象关系映射）或参数化查询；
- 外部接口不返回内部 Dataset ID、服务身份和内部错误；
- 当前版本为 `/api/v1`；删除字段、改变枚举语义或权限范围必须升级版本；
- 原 RAG 真实字段与本文冲突时，应更新 Adapter（适配层）和文档，不得伪造上游能力。

## 17. 接口验收清单

### 17.1 鉴权与越权

- [ ] 无令牌不能访问内部接口；普通员工不能访问 `/admin`；
- [ ] 外部接口提交 `dataset_ids` 返回 `422`；伪造角色也只能访问外部公开范围；
- [ ] 停用用户旧 JWT 立即失效；普通员工不能读取其他员工会话。

### 17.2 文档和 Chunk

- [ ] 多文件导入返回逐文件结果；未知上游状态不会变成成功；
- [ ] 新文档失败时旧文档仍可检索；删除不删除源文件；
- [ ] Chunk 只能查看和启停，错误索引版本返回冲突。

### 17.3 FAQ 和问答

- [ ] FAQ 只做归一化精确匹配，未命中后进入原 RAG；
- [ ] 三档 FAQ 分别生成三份文档并进入各自 Dataset；
- [ ] Redis 不可用可回退 MySQL；RAG 不可用不生成无来源答案；
- [ ] SSE 最终只能出现一个 `final` 或 `error`；系统错误不生成知识缺口。

### 17.4 数据与交付

- [ ] 响应、日志和审计使用同一 `request_id`；关键写操作有审计；
- [ ] Token 缺失为 `null`；密钥、密码和连接串不进入日志；
- [ ] 平台接口 Contract Test（契约测试）不依赖问问小安代码；
- [ ] 平台与 RAG 全部验收后才启动问问小安对接。

## 18. 执行 Agent 强制停点

以下情况必须暂停并向用户确认：

1. 开始制作实际前端页面前，先确认视觉风格、信息布局和原型；
2. 原 RAG 真实请求或响应字段与本文关键契约冲突；
3. 需要新增角色、部门权限、客户等级或产品级权限；
4. 需要修改原 RAG 检索、网络搜索、切分或生成主逻辑；
5. 需要提前接入问问小安；
6. 需要新增服务器、消息队列、定时 Worker（后台任务进程）或第二套向量数据库。

除此之外，执行 Agent 应按三份设计文档实施和验证，不得以“后续可扩展”为理由增加本期未要求的抽象和功能。
