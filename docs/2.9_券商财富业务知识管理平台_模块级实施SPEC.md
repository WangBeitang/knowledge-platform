### 0.2 全局技术栈（冻结）

- 后端：Python + FastAPI + Pydantic（`extra="forbid"`）+ SQLAlchemy 2.x（async）+ Alembic + HTTPX + PyJWT + passlib/bcrypt
- 前端：Vue 3 + TypeScript（strict）+ Vite + Element Plus + ECharts + Pinia + Vue Router；SSE 消费；导入任务轮询（不引入 WebSocket）
- 数据：MySQL（平台业务数据，独立库独立账号）+ Redis（仅 FAQ 精确缓存）
- 部署：Nginx（TLS 终止、静态托管、/api 反代）+ Docker Compose 单机

### 0.3 命名基线（Skill 与总纲 17.2 强制）

- 类/类型：职责唯一的名词，如 `UserRepository`、`DocumentService`、`RagQueryClient`、`FaqCacheStore`；禁止 `Manager` / `Helper` / `Utils` / `Common` / `Base` 前缀的含糊类。
- 方法：表达结果或副作用的动宾，如 `authenticate_user`、`import_documents`、`replace_document`、`stream_answer`、`publish_faq`、`sync_faq_document`、`analyze_faq_candidates`。
- 读取方法不得隐藏写操作；布尔方法用 `is_` / `has_` / `can_` 前缀。
- API 路径、数据库字段、状态枚举沿用冻结值，**不另造同义词**。
- 数据库字段名 / ORM 属性名 / Pydantic 字段名 / 前端 TS 类型字段名**保持单一命名事实**（snake_case），由各层显式映射，禁止出现三套命名。

### 0.4 接口契约基准

- Base Path 统一 `/api/v1`；接口明细以《API 接口设计》为准（总纲第 12 节为概要版，路径以详细版为准，如 `messages:stream`、`faq-candidates`、`sync:retry` 等冒号/连字符写法）。
- 统一响应壳 `{"request_id","data"}` / 错误壳 `{"request_id","error":{"code","message","retryable","details"}}`；`X-Request-Id` 全链路贯穿（响应头、响应体、日志、审计）。
- **不实现通用 `Idempotency-Key` 机制**：API 文档 1.3 与数据对象文档已同步修订（v1.1：删除通用幂等要求、`IDEMPOTENCY_CONFLICT` 错误码、`rag_integration_tasks.idempotency_key` 字段及唯一约束）。仅保留业务级幂等（Dataset 初始化、FAQ `content_hash`、替换与 FAQ 文档清理状态机），不新增幂等专用表。

## 2. 模块职责与依赖方向

### 2.1 后端模块职责（单一职责，单向依赖）

| 模块 | 唯一职责 | 依赖（只允许） | 不得做 |
|---|---|---|---|
| `core` | 配置、DB/Redis 连接、日志、错误模型、JWT/密码、归一化 | 无（纯基础） | 不写业务逻辑；不提供通用幂等中间件 |
| `models` | 13 张表的 ORM 定义 | core | 不含业务方法 |
| `repositories` | 全部 SQL 访问与分页/聚合查询 | models, core | 不含业务规则、不调 RAG |
| `schemas` | 请求/响应 DTO 与校验 | models（少量引用） | 不含业务逻辑 |
| `rag` | 上游 API 适配、范围策略、错误映射 | core, config | 路由层禁止直接拼上游 URL |
| `services` | 业务规则与编排 | repositories, rag, core, schemas | 不处理 HTTP 协议；不直接暴露 ORM |
| `api/v1` | 协议、鉴权、响应映射 | services, schemas, deps | 不写业务规则、不直接查库、不拼上游 URL |
| `scripts` | 幂等初始化 CLI | services, core | 非定时任务 |
| `tests` | 单元/集成/契约验证 | 全部（stub 上游） | 不依赖真实问问小安 |

依赖方向（无环）：`api → services → repositories/rag → models/core`；`schemas` 被 api 与 services 引用；`audit_service` 被各写操作 service 引用（依赖注入，不反向依赖调用方）。

### 2.2 前端模块职责

| 模块 | 唯一职责 |
|---|---|
| `api/` | 所有后端调用封装：统一鉴权头、request_id、错误码映射、SSE 流接口 |
| `router/` + `stores/auth.ts` | 路由守卫：未登录 → 登录页；员工隐藏管理菜单；**仅前端隐藏，后端仍强制校验** |
| `views/admin/*` | 管理员全部功能页 |
| `views/employee/*` | 员工问答与历史会话 |
| `components/` | 布局、Citation 卡片、任务状态、SSE 渲染等复用组件 |
| `utils/sse.ts` | 用 `fetch + ReadableStream` 消费 SSE 流（`ready→(progress|delta)*→final|error`；原生 `EventSource` 不支持 POST，禁用），断线展示状态并允许重试 |

### 2.3 核心调用链（设计锚点，实现时按此落测）

**员工内部问答（主链路）**

```text
前端 POST /api/v1/chat/sessions/{sid}/messages:stream (SSE)
→ deps.get_current_user（JWT → 会话未撤销 → 用户 active → 密码未变更）
→ ChatService.stream_answer
    → normalizer.normalize（空则 EMPTY_QUESTION）
    → FaqService.lookup_exact_faq(scopes_for_role, q)   # Redis → MySQL 回退
    ├─ 命中 → SSE final(answer_source=faq_cache) → 写消息/日志（hit_count+1）
    └─ 未命中 → RagQueryClient.submit(query, dataset_ids, service_user)
        → SSE ready → progress(rag_submit) → delta*（透传上游流）
        → final(answer, citations, trace_id) 或 error(RAG_UNAVAILABLE 等)
    → 写 chat_messages / qa_access_logs（同 turn_id；日志含 citation_count / terminal_reason_code）
    → BackgroundTasks：RagTraceClient 补取 token（可缺失 → null）
    → 本轮不直接生成知识缺口候选；候选由管理员在阶段 5 手动 analyze 日志产生
```

**文档替换（长任务状态机，失败安全）**

```text
POST /api/v1/admin/documents/{id}/replace（新文件）
→ DocumentService.replace_document
    → 创建 document_replacements(status=pending) + rag_integration_tasks(operation=document_replace)
    → 新文件导入同一 scope（RagImportClient.upload）→ 记录 rag_task_id
    → 返回 HTTP 202 + 平台 task_id（不等待导入完成）

前端轮询 GET /api/v1/admin/integration/tasks/{task_id}
→ TaskService.refresh_from_upstream 刷新上游状态
    → 新文档 active 且替换记录仍为 pending 时：
        以数据库行锁（SELECT ... FOR UPDATE 或条件 UPDATE status=pending）保证只执行一次
        → RagDocumentClient.delete(旧文档)（Milvus 物理删）
        → document_replacements.status=completed → 旧映射标 replaced
    → 新文档失败：替换记录标 failed，旧文档保持 active 可检索，展示错误摘要
```

删除旧文档的动作只由 `TaskService` 在轮询中触发并受行锁保护；任何一步失败不删除旧文档。

## 4. 接口 → 代码映射

### 4.1 全局约定

- 所有路由函数只做：解析请求 → 调 service → 组装响应；错误统一抛 `AppError`（由全局处理器映射到稳定错误码）。
- 鉴权依赖：`get_current_user`（每次请求校验签名 + 到期 + 会话撤销 + 用户 active + 密码变更时间）；`require_admin` 叠加角色校验。
- 分页参数 `page`(1) / `page_size`(20, ≤100) / `sort_by`(白名单) / `sort_order`(asc|desc)。
- **不实现通用 `Idempotency-Key`**（见 §0.4）。业务级幂等：① Dataset bootstrap 先查后建，重复执行返回已有结果；② FAQ 同范围同 `normalized_question_hash` 唯一约束 + 发布前状态检查；③ FAQ 文档同步以 `faq_sync_runs(scope, content_hash)` 已成功直接幂等返回；④ 替换删除由 §2.3 状态机行锁保证只执行一次。
- 无权访问的资源统一回 `404 RESOURCE_NOT_FOUND`（避免泄露管理资源存在性），鉴权失败回 `401`，无权限操作回 `403 PERMISSION_DENIED`。

## 5. 原 RAG 适配关系

### 5.1 适配层位置

- 唯一出口：`app/rag/` 下的 4 个 Client + `scope_policy` + `rag_errors`。
- 路由层 / services 层**禁止**直接拼上游 URL；上游 Base URL 只来自环境变量（`RAG_QUERY_BASE_URL` / `RAG_IMPORT_BASE_URL`）。
- 所有 Client 内建：连接超时、读取超时、错误映射（`rag_errors.py` → 稳定错误码）、连接池。

### 5.2 固定服务身份与范围映射（`rag/scope_policy.py` 单一事实来源）

| 身份 | `scopes_for_role` 顺序（FAQ 匹配优先级同序） | `dataset_ids_for_scopes` | 上游 `X-User-Id` |
|---|---|---|---|
| `admin` | `[admin_private, internal_shared, external_public]` | 三档 env ID | `RAG_SERVICE_USER_ADMIN` |
| `employee` | `[internal_shared, external_public]` | 两档 env ID | `RAG_SERVICE_USER_EMPLOYEE` |
| `external` | `[external_public]` | `RAG_EXTERNAL_DATASET_ID` | `RAG_SERVICE_USER_EXTERNAL` |

- 平台 DB 记录真实操作人；上游只记录服务身份与 Trace。
- 外部请求 Schema **不含** `knowledge_scope` / `dataset_id` / `dataset_ids`，出现即 `422`（`extra="forbid"` + 显式字段检查）。

### 5.3 平台动作 → 上游接口映射

| 平台动作 | 上游接口 | Client 方法 |
|---|---|---|
| 提交查询 | `POST /query`（显式传 `dataset_ids` + 平台生成的加命名空间 session_id） | `RagQueryClient.submit` |
| 读流 | `GET /stream/{session_id}` | `RagQueryClient.stream` |
| 查状态 | `GET /status/{session_id}` | `RagQueryClient.get_status` |
| 查 Trace | `GET /traces/{trace_id}` | `RagTraceClient.get_usage`（token 可缺失 → `null`） |
| Dataset 创建/查询 | `POST /datasets`、`GET /datasets`、`GET /datasets/{id}` | `RagImportClient.ensure_dataset` / `get_datasets` |
| 成员管理 | `/datasets/{id}/members` 相关 | `RagImportClient.ensure_members` |
| 单文件上传 | `POST /upload`（`files`、`dataset_id`、`visibility`） | `RagImportClient.upload_file` |
| 任务查询 | `GET /status/{task_id}` | `RagImportClient.get_task_status` |
| 文档列表/详情/任务 | `GET /documents`、`GET /documents/{id}`、`GET /documents/{id}/tasks` | `RagDocumentClient.get_document` 等 |
| Chunk 列表/详情/启停 | `GET /documents/{id}/chunks`、详情、`PATCH .../enabled` | `RagDocumentClient.list_chunks` / `set_enabled` |
| 重建/删除 | `POST /documents/{id}/rebuild`、`DELETE /documents/{id}` | `RagDocumentClient.rebuild` / `delete` |

要点：页面多文件上传 ≠ 上游批量；适配层**循环单发**并保留逐文件任务。上游会话 ID 由平台生成或加命名空间，避免内外会话碰撞。

### 5.4 超时、重试与错误映射（冻结自 API 15）

| 调用 | 超时 | 重试 |
|---|---:|---|
| 健康/列表/详情 | 3～10s | 网络错误最多 2 次，指数退避 |
| 提交 RAG 查询 | 15s | 确认接收后不重复提交 |
| SSE 读取 | 上游合理上限 | 断开后查状态，不自动生成第二问 |
| 文件上传 | 按大小配置 | 无业务幂等保证时不自动重传 |
| Trace 查询 | 5s | 最多 2 次，最终缺失 Token 为 `null` |

错误映射规则：连接失败/超时 → `503 RAG_UNAVAILABLE` / `504 RAG_TIMEOUT`（可重试）；上游返回违反契约 → `502 RAG_BAD_RESPONSE`；上游未知状态**不得映射为成功**，保留原值并映射 `running` 或明确失败，由适配层记原因。

### 5.5 兼容边界（冻结）

- 设备运维 Dataset 不动；券商三档 Dataset 由平台 env 显式指定。
- 原 RAG 联网检索逻辑保持；"只能访问外部 Dataset" ≠ "答案只来自本地公开文档"（已接受边界）。
- 上游新字段先由适配层兼容裁剪，不直接穿透使前端契约漂移；契约冲突时更新 Adapter 与文档，不伪造上游能力。
